# Досье для проверки юристом

Всё юридическое содержимое продукта «Рестарт» — правила, поля анкеты, тексты документов —
собрано здесь в виде чек-листа. Ничто из перечисленного не является юридическим заключением:
это плейсхолдеры, написанные разработчиками по мотивам 127-ФЗ (редакция, действующая с
21.06.2026) и ожидающие подтверждения или правок юриста. До завершения проверки каждый
сгенерированный документ несёт баннер «ШАБЛОН-ПЛЕЙСХОЛДЕР — НЕ ПРЕДНАЗНАЧЕН ДЛЯ ПОДАЧИ В СУД»,
а интерфейс предупреждает пользователя о том же.

**Как устроены правки.** Юридическое содержимое отделено от кода:

| Что | Где лежит | Как править |
|---|---|---|
| Правила скрининга | `src/main/java/ru/restart/app/eligibility/domain/EligibilityRules.java` | правка текста/порогов — маленькое изменение кода |
| Состав анкеты, обязательность, форматы полей | `src/main/resources/casefile/sections.yml` | один YAML-файл, без изменений кода |
| Тексты шести документов | `src/main/resources/doctemplates/2026-06-21.1/*.mustache` | текстовые файлы; новая редакция закона = новая папка-версия + одна строка в `manifest.yml` |
| Общие юридические блоки (шапка, реквизиты заявителя, подпись) | `.../partials/*.mustache` | определены один раз, используются во всех документах |

---

## 1. Скрининг «подходит ли самостоятельная процедура» (8 вопросов)

Логика: любой «маркер сложности» → честный ответ «тебе лучше с юристом» с причинами.
Дело считается подходящим только при отсутствии всех маркеров.

Текущие маркеры: долг < 500 тыс. ₽ или > 3 млн ₽; автомобиль; недвижимость кроме
единственного жилья; бизнес/доля; брак или развод; продажа/дарение ценного имущества за
последние 3 года; долги не только потребительские; зарубежные активы или судебные споры.

**Вопросы юристу:**
- [ ] Корректны ли пороги 500 тыс. — 3 млн ₽ как границы «простого» дела? (Продуктовое
      ограничение, не норма закона — подтвердить осознанность выбора.)
- [ ] Достаточен ли набор маркеров? Чего не хватает (например: статус ИП сейчас/в прошлом,
      поручительства, залоговое имущество, текущая процедура банкротства, судимость по
      экономическим статьям)?
- [ ] Проверить формулировки причин (см. файл) — они показываются пользователю дословно.

## 2. Анкета — состав и обязательность (`sections.yml`)

16 разделов: личные данные, паспорт, адрес регистрации, контакты, занятость, доход,
семейное положение, иждивенцы, кредиторы, долги, счета, имущество, недвижимость, транспорт,
суды, исполнительные производства. У каждого раздела проставлена ссылка на норму
(`statutoryBasis`) — все ссылки черновые.

**Вопросы юристу:**
- [ ] Соответствует ли состав разделов требованиям ст. 213.4 127-ФЗ к заявлению гражданина
      и приложениям? Что лишнее, чего не хватает?
- [ ] **Известный пробел:** нет раздела «сделки с имуществом за последние 3 года» (описи
      сделок). Скрининг отсеивает таких пользователей, но требуется ли раздел в анкете и
      документах для остальных?
- [ ] Верно ли расставлена обязательность разделов (`mandatory`) и полей (`required`)?
      Сейчас обязательны: личные данные, паспорт, адрес, контакты, занятость, доход,
      семейное положение, кредиторы, долги. Необязательны: иждивенцы, счета, имущество,
      недвижимость, транспорт, суды, приставы.
- [ ] Достаточно ли полей в каждом разделе (например, у кредитора: название, ИНН, адрес,
      сумма, основание — нужны ли ОГРН, БИК, реквизиты договора, дата возникновения)?
- [ ] Подтвердить/уточнить каждую ссылку `statutoryBasis`.

## 3. Автоматические проверки (валидация)

Детерминированные правила: обязательность полей; дата в формате ГГГГ-ММ-ДД; серия паспорта —
4 цифры, номер — 6 цифр; ИНН — 10/12 цифр с контрольными числами ФНС; суммы ≥ 0; дубликаты
кредиторов по паре «название + ИНН» (без учёта регистра); пустые обязательные разделы.
Тексты ошибок — разговорные, показываются пользователю дословно.

**Вопросы юристу:**
- [ ] Нужна ли проверка контрольного числа СНИЛС (сейчас — свободный текст)?
- [ ] Корректен ли признак дубликата кредитора «название + ИНН»?

## 4. Шесть документов (`doctemplates/2026-06-21.1/`)

Заявление о признании банкротом; список кредиторов; опись имущества; сводка задолженности
(вспомогательная); перечень прилагаемых документов; чек-лист подачи (памятка пользователю,
в суд не подаётся).

**Вопросы юристу:**
- [ ] Список кредиторов и опись имущества: должны соответствовать формам, утверждённым
      Минэкономразвития (приказ — реквизиты в шаблонах помечены ПЛЕЙСХОЛДЕР). Дать точные
      реквизиты действующих форм; при необходимости — перестроить структуру шаблонов под них.
- [ ] Заявление: проверить вводную и просительную части (сейчас: признать банкротом; ввести
      процедуру по ст. 213.6; утвердить финуправляющего из СРО — название СРО помечено
      «[СРО — ПЛЕЙСХОЛДЕР]»: как выбирается СРО и что писать?).
- [ ] Перечень приложений: сверить с п. 3 ст. 213.4 (сейчас 11 пунктов, включая госпошлину
      и депозит на вознаграждение финансового управляющего — указать действующие суммы).
- [ ] Общие блоки: шапка «В [суд]», блок реквизитов заявителя, форма подписи — достаточно ли
      реквизитов (например, СНИЛС и ИНН в шапке)?

## 5. Определение суда

Суд пока не определяется: в документах стоит «Арбитражный суд по месту регистрации
должника — [УТОЧНЯЕТСЯ]».

- [ ] Подтвердить правило подсудности (по месту жительства должника, ст. 33 127-ФЗ?) и
      согласовать источник справочника «регион → арбитражный суд» для автоподстановки.

## 6. Обещания продукта и персональные данные

- Продукт нигде не обещает списание долгов; результат скрининга «не подходит» формулируется
  честно («тебе лучше с юристом»). — [ ] проверить все пользовательские тексты на
  недопустимые обещания.
- [ ] Анкета собирает паспорт, ИНН, СНИЛС, доходы, долги: согласовать текст согласия на
      обработку персональных данных (152-ФЗ) и политику — в продукте их пока нет.

---

**Процесс:** ответы/правки по каждому пункту вносим обычными PR (YAML и тексты шаблонов),
изменённые документы автоматически перепроверяются golden-тестами. После закрытия всех
пунктов снимаем баннер «не для подачи» отдельным осознанным изменением.
